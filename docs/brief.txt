For many years I have done a dinner party trick where I work out in my head or on a scrap of paper amusing alter egos using all the letters in the name of someone at the table. examples David McNair=Vicar Dan Dim, Dr Adam Vinci,  Ivan Dim-Card; Ola Kristiansen=Rik Sensational; Neil McGovern=Vince Mongrel; Catherine Garnier=Harriet Car-Engine.  I want to build a pattern-driven constrained anagrammer tool to help me do the same at scale and to be able to exhaustively find all the great alter egos I may have missed. Am aware that the state space can be very large for anagram combinations, and want to get funniest results out of fewest iterations so intent is to use several strategies to limit iterations, especially unfunny ones. Strategy: A timed cut-off and resumable search state so that over multiple runs you can eventually hit all combinations without rerunning old junk. Strategy - use tokens (forename, honorific, initials, prefix, suffix, surname, title) to make strict template patterns eg {forename} {surname}, {title} {forename} {surname}-{surname}, I have a couple of dozen of these. Strategy. Maximal example: {title} {forename} {initials} {prefix:' '} {surname:2}{suffix:'-'} {honorific} Mr John I.P. de la Kinky-Boot-ilicious IV. I have curatable lists of words for each token type - words within each type may be designated (if feature enabled for the token type) funny, boring or remainder; additionally words may be gendered M/F or unisex (if feature enabled for the token type) - i already have separate files for each token type eg forenames/boring_boys, boring_girls, boring_both, funny_boys, funny_girls, funny_both, remainder_boys, remainder_girls, remainder_both. Am open to building new files if you have good sources. The surnames file is where the fun largely happens - there are largely no actual surnames in the curated surnames file, just funny/remainder/boring ordinary words that can be matched, repeats are allowed for multiple tokens eg :2 if source letters permit. Strategy: on the fly curation means after each pass matching words in each token list may be removed (temporarily or permanently from curated list), or designated funny/boring/remainder; missing words that I spot should also be addable to a token type's list.  Strategy: Slight allowance for “nearly words” if real words won’t fill the gap (slightly bent spellings, slang, obscure surnames) acceptable if they’re funny? Foreign words that are well known in english are acceptable. Strategy: funny words should be matched first. Strategy: keep a file for each list of results from a given source name. Strategy: allow Include boring/nearly words to be toggled. Anything else you need to know?
